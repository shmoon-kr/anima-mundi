# 1단계: 최소 세계 — anima 파티 6인이 Mundi 에서 사냥한다

## 목표
tbaMUD 세계를 읽어 들인 Rust 엔진에서, anima 런타임의 파티 6인(현재 tbaMUD 에서 도는 그대로)이 접속해 사냥·휴식·성장한다.
사람은 `anima play`(또는 간단한 텔넷)로 영어나 한국어 화면을 본다.
tbaMUD 위의 같은 파티와 성장 지표(`anima stats`, D34 기준)를 비교할 수 있다.

## 범위
- 세계: tbaMUD 세계 파일 전부를 읽되, 1단계 플레이 검증은 Midgaard·초보 지역·anima 사다리 상위 지역(New Thalos 등)
- 규칙: 파티가 실제로 쓰는 것만 — 이동(지형별 이동력), 보기, 근접 전투와 피해 문구, kick·bash·rescue·backstab·magic missile·
  cure light·armor·create food·create water·remove poison, 그룹·따라가기·autoassist·autoloot/gold/split, 사망·시체·부활,
  자세(서기·쉬기·자기)와 회복, 배고픔·목마름, 경험치(그룹 분배, 레벨 표, 사망 시 절반), 독, 어둠과 광원, 문(열기·잠김), 존 리셋, 몹의 배회·선공
- 상점은 사기·팔기·목록만, 길드는 연습만 (anima 파티의 장보기·연습이 돌 정도)
- 다국어: 1단계에서 나오는 모든 메시지의 영어·한국어 Fluent 템플릿, 초보 지역 콘텐츠의 한국어 번역 파일(LLM 번역 후 검수), 한국어 키워드·명령 별칭

## 마일스톤
- **M0 뼈대와 결정** ★
  - Cargo 워크스페이스 구조 제안(예: `mundi-world`, `mundi-sim`, `mundi-render`, `mundi-net`, `mundi-store`), 의존성 최소(tokio, serde, 웹소켓 크레이트 하나)
  - 라이선스 결정(D3) 반영, `third_party/tbamud/` + `NOTICE.md`
  - 엔진 계약 버전 고정: anima `PROTOCOL.md` 의 어느 버전을 구현하는지 명시
- **M1 명세 추출: `docs/MECHANICS.md`** ★ (코드보다 먼저, 사용자 확인)
  - 위 범위의 규칙을 tbaMUD 소스에서 정리: 공식·표·순서·예외, 출처 파일:줄. 코드는 옮기지 않는다 (D9)
  - 틱 구조(전투 라운드, 회복, 존 리셋, 게임 시간), 위치·자세에 따른 명령 허용, 메시지가 누구에게 어떤 관점으로 가는지(act 의 TO_CHAR/TO_VICT/TO_ROOM 규칙)
- **M2 콘텐츠 형식과 변환기** ★ (형식 확인)
  - 새 콘텐츠 형식(YAML) 스키마: 존·방·몹·물건·상점·리셋, 문자열 ID, 언어별 번역 파일 구조(D10, D11)
  - tbaMUD 변환기: `.wld/.mob/.obj/.zon/.shp` → 새 형식 (+ vnum 대응표). anima 의 파서를 참고. 모든 존이 오류 없이 변환되고 스키마를 통과
  - 엔진 로더는 새 형식만 읽는다. 로드 시간·개수 확인
- **M2b 상태 저장**: SQLite 스키마(계정, 캐릭터, 소지품·장비, 세계의 동적 상태). 서버를 껐다 켜도 캐릭터와 소지품이 남는다
- **M3 시뮬레이션 코어**: 틱 스케줄러, 결정론 RNG(시드), 엔티티와 ID, 이동·보기·자세·회복. 같은 시드·같은 입력 → 같은 결과 테스트
- **M4 지각과 렌더링**: 사건 → 지각 필터 → 수신자별 렌더링(관점, 언어). Fluent 템플릿과 한국어 조사 함수 ★(확인). 문자 폭
- **M5 네트워크**: WebSocket 서버(엔진 계약 이벤트 + 렌더링된 문장, 명령 수신), 로그인(핸들·비밀번호, 비밀 보호 규칙), 간단한 텔넷 게이트웨이(문장 스트림)
- **M6 규칙 구현**: 범위의 규칙을 MECHANICS.md 기준으로. 각 규칙마다 단위 테스트, 가능하면 tbaMUD 실서버와 같은 상황의 결과 비교
- **M7 anima 연결**: anima 저장소에 WebSocket 어댑터 추가(텍스트 해석 없음). 6인 파티가 Mundi 에서 로그인·그룹·사냥·야영·사망 후 복귀
- **M8 비교와 다국어 확인**: 같은 파티를 tbaMUD 와 Mundi 에서 각 1시간, `anima stats` 성장·사망·이탈 비교. 한국어 화면으로 사람이 둘러보기

## 범위 밖
전체 기술·주문, 퀘스트·특수 동작 스크립트, 상점 경제 균형, 스냅샷·분기·시간 가속(설계에 자리만), 플랫폼(GraphQL)·웹 클라이언트·관전·빙의,
LLM NPC·빌더, 공정성 장치 구현(설계 메모만), Postgres(1단계는 SQLite), 텔넷 게이트웨이의 협상 기능 전체.

## 완료 조건
- MECHANICS.md 가 사용자 확인을 받았고, 구현의 각 규칙이 그 문서의 절을 가리킨다
- tbaMUD 세계 파일 전부가 새 형식으로 변환되어 스키마를 통과하고, 엔진이 새 형식만으로 로드한다
- 서버를 재시작해도 캐릭터·소지품·장비가 DB 에서 그대로 돌아온다
- 같은 시드·같은 입력의 두 실행이 같은 이벤트 로그를 낸다
- 코드 어디에도 소켓에 문장을 직접 쓰는 곳이 없다 (렌더러만 문장을 만든다 — 검사 테스트)
- anima 파티 6인이 Mundi 에서 1시간 무개입으로 사냥하고, 성장·사망·이탈이 tbaMUD 실행과 비슷한 범위다 (차이는 원인과 함께 기록)
- 같은 장면을 영어 사용자와 한국어 사용자가 동시에 각자의 언어로 본다. 한국어 조사가 맞고, 한국어 키워드로 대상을 지정할 수 있다
- 엔진 코드에 tbaMUD 코드·주석이 옮겨지지 않았다 (리뷰 체크), tbaMUD 유래 데이터는 `third_party/tbamud/` 에만 있다

## 진행 방식
- 작업 시작 전 이 문서와 `DECISIONS.md` 를 읽는다
- 큰 결정(크레이트 구조, 템플릿 형식, 저장 방식)은 제안 후 사용자 확인, `DECISIONS.md` 에 기록
- 사용자는 Rust 에 익숙하지 않다: 설명은 개념과 동작 위주로, 결과는 테스트·실행·지표로 보여 준다
