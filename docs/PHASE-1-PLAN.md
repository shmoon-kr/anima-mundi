`PHASE-1.md` 의 M0~M8 을 그대로 따르되 한 가지를 바꾼다: **규칙을 넓히기 전에 끝에서 끝까지 이어지는 얇은 뼈대(S3)를 먼저 만든다.**
로그인 → 방 보기 → 이동 → 말하기가 WebSocket 으로 돌고, 상태가 DB 에 남고, 같은 시드로 같은 로그가 나오는 것까지.
구조의 실수(크레이트 경계, 이벤트 흐름, 결정론)는 규칙이 적을 때 고치기 싸다. 사용자에게도 이때부터 "돌아가는 것"을 보여 줄 수 있다.
S1(명세)과 S2(변환기)는 서로 의존하지 않아 같이 간다.

  | `mundi-server` (실행 파일) | 위를 묶는다 | 전부 |

  **지각은 시뮬레이션의 사실이다** (원칙 2): "이 캐릭터가 지금 이걸 볼 수 있나"는 빛·자세·위치·실명·투명으로 정해지는 시뮬레이션 상태다.
  그래서 지각 필터는 `mundi-sim` 안에 있다. 흐름은 하나뿐이다:
  ```
  사건 발생 → 지각 필터 (수신자 목록 + 각자가 보는 내용: 어둠이면 몹 목록 없음, 안 보이면 "someone")
            → 수신자별 이벤트(mundi-protocol) ─┬→ 에이전트: 그대로 전송
                                               └→ 사람: mundi-render 가 문장으로 → 전송
  ```
  렌더러에 지각 필터가 있으면 문장만 걸러지고, 에이전트에게 가는 이벤트는 필터를 건너뛸 수 있다(어두운 방에서 에이전트만 몹 목록을 받는다).
  필터를 sim 에 두면 에이전트와 사람이 받는 정보가 **구조적으로** 같다: 렌더러는 이미 걸러진 이벤트만 받는다.

  원칙을 **의존 관계로** 강제한다: `mundi-sim` 은 네트워크·DB·렌더링 크레이트에 의존하지 않는다(문장을 만들 수도, 소켓에 쓸 수도 없다).
  `mundi-render` 는 `mundi-sim` 에 의존하지 않고 `mundi-protocol` 의 수신자별 이벤트만 받는다. 문장은 `mundi-render` 만 만들고,
  `mundi-net` 은 수신자별 이벤트와 렌더러의 출력 타입만 받는다. "소켓에 문장을 직접 쓰는 곳이 없다"는 완료 조건이 컴파일러로 지켜진다
- [x] YAML 크레이트: **serde-saphyr** (`serde_yaml` 은 유지보수 종료). 설치할 때 최신 판·serde 연동·긴 문자열(블록 스칼라) 처리를 확인한다
- [x] 엔진 계약 버전 ★: anima `PROTOCOL.md` **v0 1부**를 구현하고, Mundi 가 처음으로 채울 수 있는 것을 같이 정한다: — D14

## S3. 걷는 뼈대 (M2b 일부, M3 일부, M4 일부, M5 일부)
얇게, 끝에서 끝까지. 영어 한 언어, 사람 한 명.
- [ ] `mundi-protocol`: S3 에 필요한 이벤트·명령 타입(접속·로그인·방·이동·말·프롬프트)과 봉투
- [ ] `mundi-sim`: 엔티티 저장소(세대 붙은 ID), 방·캐릭터, 명령 대기열 → 틱(1초 10회)에서 처리, 사건 발생, 지각 필터(이 단계는 "같은 방에 있다"만). 명령: `look`, 방향 이동(지형 이동력), `say`, `quit`
- [ ] 결정론: 시뮬레이션은 한 스레드, RNG 는 시드 하나(ChaCha). 네트워크에서 들어온 명령은 **틱 번호와 함께** 입력 로그에 남기고, 입력 로그 재생 = 같은 사건 로그
- [ ] `mundi-render`: 사건 → 받는 사람 → 영어 문장(Fluent). 관점 셋(나·대상·나머지)부터
- [ ] `mundi-store`: 계정·캐릭터(위치) 저장과 복원

## S5. 규칙 (M6)

1. 자세·회복·배고픔/목마름·먹고 마시기 → 2. 물건·장비·광원 → 3. 몹 리셋·배회·선공 → 4. 근접 전투·피해 문구·사망·시체·경험치 →
5. 그룹·따라가기·autoassist·autoloot/gold/split → 6. 기술·주문 → 7. 독 → 8. 문 → 9. 상점·길드

- 확인: 규칙마다 테스트가 MECHANICS 절을 가리킨다
