# 결정 기록

각 항목: 결정 / 이유 / 날짜. 뒤집으려면 새 항목으로 추가하고 이전 항목을 가리킨다.

## D1. 이름: Anima Mundi (2026-10-03)
anima 의 VISION 에서 "나중에 새로 쓸 엔진"으로 정해 둔 이름. 개별 영혼(anima)들이 사는 세계의 영혼(anima mundi).
저장소 `anima-mundi`, 크레이트 `mundi`.

## D2. 엔진은 새로, 콘텐츠와 규칙은 tbaMUD 에서 (2026-10-03)
tbaMUD 는 완성된 문장을 코드 곳곳에서 바로 보내는 구조라 다국어·지각 기반 이벤트를 넣으려면 사실상 다시 써야 한다.
세계 파일과 게임 규칙(전투·기술·회복·경험치·상점 등)은 그대로 쓴다: 첫날부터 큰 세계, 검증된 균형.
구조(모듈, 데이터 흐름, 출력 방식)는 처음부터 새로 짠다.

## D3. 라이선스: 엔진 코드는 AGPL-3.0 (2026-10-03, 결정)
- 엔진 코드: **AGPL-3.0** (`LICENSE`, gnu.org 원문). 오픈소스로 인정되면서, 이 엔진으로 네트워크 서비스를 하는 쪽은 수정한 코드를 공개해야 해서
  무임 SaaS 를 견제한다. 저작권자는 별도 상용 라이선스를 팔 수 있다(이중 라이선스)
- 외부 기여를 받기 시작하기 전에 기여자 동의서(CLA)를 마련한다: 없으면 기여분은 상용 라이선스에 넣을 수 없다
- 검토한 대안: PolyForm Noncommercial(상업 이용 금지, OSI 오픈소스 아님), MIT(최대 확산, anima 의 선택)
- `third_party/tbamud/`: DikuMUD/CircleMUD/tbaMUD 라이선스(비상업, 원작자 표기). 엔진 라이선스와 무관하게 이 부분은 상업 이용 불가
- 상업화하려면 tbaMUD 콘텐츠를 고유 콘텐츠로 대체해야 한다 (로드맵 5). 이 기록은 법률 자문이 아니다: 상업화 전에 검토를 받는다

## D4. Rust (2026-10-03)
코드 대부분을 AI 가 쓴다: 엄격한 타입과 컴파일러가 실행 전 검증기 역할을 한다. 에이전트 수천 명 규모의 성능 여유.
존·퀘스트 같은 콘텐츠 로직은 Rust 에 넣지 않고 스크립트 계층·데이터로 둔다.

## D5. 엔진 계약 = anima PROTOCOL 1부, WebSocket (2026-10-03)
실시간은 WebSocket 양방향(이벤트 + 렌더링된 문장 / 명령). anima 런타임은 WebSocket 어댑터만 추가하면 붙는다(텍스트 해석 불필요).
조회·관리는 별도 플랫폼(Python, GraphQL), MCP 는 anima 런타임. 엔진은 WebSocket 하나만 연다. 텔넷은 게이트웨이로.

## D6. 출력은 사건, 문장은 수신자별 렌더링 (2026-10-03)
다국어와 지각 기반 정보를 위해. 코드가 문장을 직접 소켓에 쓰지 않는다. 같은 사건이 사람에게는 그 사람의 언어 문장으로,
에이전트에게는 이벤트로(원하면 문장도) 간다.

## D7. 이름 체계: 영문 핸들 + 언어별 표시 이름 (2026-10-03)
명령에 쓰이는 식별자는 모두가 입력할 수 있어야 하고, 유니코드 이름은 모양이 같은 다른 문자로 사칭할 수 있다.
핸들은 ASCII·유일, 표시 이름은 언어별 선택. 대상 지정은 둘 다 된다.

## D8. 명령은 영어 기준, 언어별 별칭 (2026-10-03) — 별칭 부분은 D17 로 대체
명령은 의도로 해석되므로 별칭은 저렴하다. 사람이 친 말(say/tell)은 번역하지 않는다.

## D9. 명세 먼저, 구현은 명세를 보고 (2026-10-03)
tbaMUD 소스를 읽어 규칙을 `docs/MECHANICS.md` 에 사실·공식·표로 정리하고(출처 파일:줄), 구현은 그 문서를 기준으로 한다.
코드·주석·구조를 옮기지 않는다: 구조를 새로 짜기 위해서이고, 엔진 코드를 tbaMUD 라이선스로부터 분리하기 위해서다.
수치표·메시지 문구·세계 파일은 데이터로 `third_party/tbamud/` 에만 둔다.
(완전한 분리를 보장하지는 않는다. 상업화 단계에서는 법률 검토가 필요하다.)

## D10. 콘텐츠는 새 형식의 파일, 상태는 DB (2026-10-03)
둘은 성격이 다르다.
- **콘텐츠**(세계 정의: 존·방·몹·물건·상점·리셋·수치표): 정적이고, 사람과 LLM 이 편집하고, 버전 관리·리뷰·diff 가 필요하다 → git 의 데이터 파일.
  낡은 건 "파일"이 아니라 tbaMUD 의 형식(`.wld` 등 위치 기반 텍스트, `~` 구분)이다. 새 형식은 YAML(긴 설명이 읽기 좋다) + JSON Schema 검증 ★
- tbaMUD 파일은 **변환기**로 한 번 새 형식으로 옮긴다. 원본과 변환 결과 모두 `third_party/tbamud/` (라이선스). 엔진은 새 형식만 읽는다
- **상태**(계정, 캐릭터, 소지품·장비, 바닥의 물건·시체, 몹의 위치와 체력, 경제, 소유권): 자주 바뀌고, 충돌 시 잃으면 안 된다 → DB.
  1단계 SQLite, 나중에 Postgres. tbaMUD 의 플레이어 파일·물건 파일 방식은 쓰지 않는다
- 이벤트 로그(재생·통계용)는 추가 전용 기록 (파일 또는 DB 테이블)
- ID: 새 콘텐츠는 이름공간 문자열 ID(`midgaard:temple_square`). 변환된 tbaMUD 콘텐츠는 vnum 대응표를 함께 둔다

## D11. 다국어: 영어 기본 + 언어별 덧씌움 파일, 메시지는 Fluent (2026-10-03) ★
- **기본 언어는 영어.** 콘텐츠 파일의 문자열은 영어로 쓰고, 모든 문자열은 안정된 ID 로 찾을 수 있다
- **번역은 언어별 덧씌움 파일**(`content/<zone>/` 옆에 `locales/ko/<zone>.yaml`, ID → 번역). 기본 파일을 건드리지 않고 언어를 더할 수 있고,
  LLM 일괄 번역과 사람 검수가 파일 단위로 된다. 번역이 없으면 영어로 대체
  (대안: 콘텐츠 파일 안에 `{en, ko}` 를 함께 쓰는 방식. 작성은 편하지만 언어가 늘수록 파일이 무거워진다)
- 번역 대상: 방 이름·설명, 몹·물건의 짧은 이름·긴 설명, 추가 설명, 출구에서 보이는 글, 상점 대사. ~~대상 키워드, 문 이름 키워드~~ → 번역하지 않는다 (D17)
- **엔진 메시지**(전투 문구, 시스템 응답)는 Project Fluent 형식(`.ftl`, Rust `fluent-rs`). 문법 기능(선택자, 복수, 사용자 함수)이 있어
  한국어 조사 함수(`{ JOSA($actor, "이가") }`)와 영어 대명사·단복수를 같은 틀로 다룬다. tbaMUD 의 피해 문구표 등은 변환해서 `.ftl` 로
- ~~명령 별칭도 언어별 파일~~ → 없다 (D17)

## D12. 변환된 tbaMUD 콘텐츠의 ID 는 `tba:<존>:<vnum>` (2026-10-03)
예: `tba:30:3001`. vnum 만으로도 유일하지만, 사람이 ID 를 읽을 때 존이 바로 보이도록 존 번호를 넣는다.
존 번호는 vnum 에서 계산되는 값이므로 변환기가 넣고, 로더는 두 값이 맞는지 검사한다. vnum 대응표는 함께 둔다. 새 콘텐츠는 `이름공간:이름`(D10)

## D13. 크레이트 구조: 지각은 시뮬레이션 안, 계약 타입은 따로 (2026-10-03)
`mundi-protocol`(계약 타입) · `mundi-content` · `mundi-convert` · `mundi-sim` · `mundi-render` · `mundi-store` · `mundi-net` · `mundi-server`.
- **지각 필터는 `mundi-sim` 안.** "이 캐릭터가 지금 이걸 볼 수 있나"는 빛·자세·위치·실명·투명으로 정해지는 시뮬레이션의 사실이다.
  사건 → 지각 필터(수신자와 각자 보는 내용) → 수신자별 이벤트 → 에이전트에겐 그대로, 사람에겐 렌더러를 거쳐 문장. 렌더러에 두면 문장만 걸러지고
  에이전트에게 가는 이벤트가 필터를 건너뛸 수 있다(원칙 2 위반)
- **`mundi-protocol`** 은 sim·render·net 이 공통으로 의존하는 계약 타입. 렌더러는 sim 에 의존하지 않는다
- 원칙은 의존 관계로 강제하고 테스트로 지킨다(`crates/mundi-server/tests/architecture.rs`): sim 은 render·store·net 과 그 라이브러리(tokio, rusqlite, fluent)에
  닿지 않고, render 는 sim 에, net 은 sim·store 에 닿지 않는다. 새 크레이트는 규칙표에 넣어야 테스트가 통과한다

## D14. 엔진 계약: anima PROTOCOL v0 1부 + 네 가지 추가 (2026-10-03)
Mundi 는 anima `PROTOCOL.md` v0 1부를 구현하고, 텍스트 어댑터로는 채울 수 없던 것을 채운다(호환 추가, anima 와 함께 v0.x 로 올린다):
- 모든 엔티티의 고유 `id` (v0 에 선택 필드로 자리만 있던 것)
- 사람용 **렌더링된 문장** (수신자의 언어·관점, 이벤트와 함께)
- 정확한 수치 (`damage` 등)
- 접속 시 클라이언트가 원하는 **언어** (`lang: en|ko`, 없으면 영어)
의도 명령(`move`, `attack(id)`)은 1단계에서 텍스트 명령으로 대신하고 자리만 둔다

## D15. tbaMUD 변환기는 Rust (2026-10-03)
`mundi-convert` 는 `mundi-content` 의 타입으로 쓴다. 로더와 같은 타입이라 "변환기가 쓴 것을 로더가 그대로 읽는다"가 컴파일러로 보장된다.
anima 의 Python 파서(`anima/memoria/importers/tbamud.py`)는 대조용(같은 개수·같은 값)

## D16. ID 에 종류를 넣는다: `tba:<존>:<종류>:<vnum>` (2026-10-03, D12 를 고침)
tbaMUD 는 방·몹·물건의 번호를 따로 매긴다: 초보자 지역에는 방 18602, 몹 18602, 물건 18602 가 모두 있다. `tba:186:18602` 만으로는 무엇인지 모른다.
그래서 종류를 ID 에 넣는다: `tba:186:room:18602`, `tba:186:mob:18602`, `tba:186:obj:18602` (상점은 `shop`, 존은 `tba:186`).
ID 하나가 세계 전체에서 유일해서, 프로토콜의 `id`, 콘텐츠 안의 참조, 번역 덧씌움 파일이 맥락 없이 통한다(덧씌움 파일은 종류별 구역 없이 평평한 목록).
존 번호는 사람이 읽기 위한 것이라 남기고(D12), 로더는 vnum 과 존이 맞는지 검사한다

## D17. 명령은 영어만 (2026-10-03, D8 의 별칭과 D11 의 키워드 번역을 대체)
명령어와 대상 키워드는 영어 하나뿐이다. 언어별 명령 별칭(`봐`, `북`)과 한국어 대상 키워드(`공격 오크`)는 두지 않는다.
번역 파일에는 키워드가 없다. 한 세계에 명령 문법이 하나라, 에이전트·사람·언어가 달라도 같은 명령이 같은 일을 한다.
한국어 화면에서 무엇을 쳐야 하는지는 D18 이 보여 준다. 사람이 친 말(say/tell)은 여전히 번역하지 않는다(D8)

## D18. 한국어 화면에 영어 키워드를 괄호로 붙인다 (2026-10-03, 사용자 제안)
`구덩이 짐승(beast)이 당신을 노려보고 있다.` 렌더러 한 곳의 규칙이고 콘텐츠는 그대로다(키워드는 이미 콘텐츠에 있다).
- **괄호에는 칠 수 있는 단어**: 이름(the pit beast)이 아니라 키워드. 그 방 안에서 겹치지 않는 키워드를 고르고(초보자 지역의 `newbie` 여럿 → `clueless`, `zombie`),
  그래도 겹치면 `2.newbie` 처럼 서버가 받는 번호 표기
- **조사는 괄호 앞의 한국어로**: `짐승(beast)이` — 받침은 "짐승"으로 판단한다. 괄호 안 영어로 판단하면 틀린다 (S4 조사 설계에 포함)
- **붙이는 자리**: 명령의 대상이 되는 자리만 — 방의 몹·물건 목록, 문과 출구, `look` 으로 본 대상, 소지품·장비 목록. 방 설명 같은 긴 글과 전투 문구에는 기본으로 붙이지 않는다
- **끌 수 있다**: 표시 설정 `always | targets | off`, 기본 `targets`. 처음 온 사람은 배우기 쉽고, 익숙한 사람은 깔끔하게 본다
- 덤으로 영어 사용자와 한국어 사용자가 같은 방에서 같은 단어로 말이 통한다

## D19. 번역은 필요한 곳부터, 로컬 LLM 배치로, Claude 는 용어집과 표본 검수만 (2026-10-03, 사용자 제안)
영어로 게임은 돈다. 번역은 늦어도 된다.
- **범위**: 1단계는 초보자 지역과 Midgaard 만. 이후로는 사람과 파티가 실제로 가는 지역부터, 아무도 안 가는 지역은 나중에
- **대량 번역은 로컬 LLM**(LM Studio, 밤새 배치). 측정(2026-10-03, qwen3.8-27b, 생각 끔): 6.8 토큰/초, 원문 약 190 단어/분.
  1단계 두 지역(이름·설명 약 6천 단어, 몹·물건 설명 포함하면 더)은 1시간 안쪽, 세계 전체(약 100만 단어)는 약 88시간
- **Claude 는 품질이 중요한 곳에만**: 먼저 **용어집**(지명 Midgaard·Moria, 반복되는 몹 이름, 길드 이름)을 만들어 로컬 모델이 존마다 다르게 옮기지 않게 하고,
  사람이 많이 가는 지역의 결과를 표본 검수한다
- **검사**: 출력 JSON 의 ID·키가 원문과 같다, **한글 외 문자 섞임 거부**(측정에서 "더糟糕한" 처럼 한자가 섞였다 → 거부하고 다시), 용어집 단어가 지켜졌다,
  빠진 필드는 누락 목록(S2 번역 누락 검사)
- **원문이 바뀔 때만 다시**: 번역마다 영어 원문의 해시를 함께 저장하고, 원문이 바뀐 항목만 다시 번역한다
